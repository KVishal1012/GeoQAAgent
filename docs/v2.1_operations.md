# GeoQA Agent V2.1 Operations Runbook

## Deployment target

V2.1 targets a single-host internal deployment. The default runtime is a containerized Streamlit app backed by a mounted `outputs/` volume.

## Minimum production configuration

- `OPENAI_API_KEY`
- `GEOQA_LLM_MODEL`
- `GEOQA_OUTPUT_ROOT`
- `GEOQA_AGENT_REPORT_ENABLED`
- `GEOQA_OPENAI_TIMEOUT_SECONDS`
- `GEOQA_OPENAI_MAX_RETRIES`
- `GEOQA_OPENAI_RETRY_BACKOFF_SECONDS`

Use `.env.example` as the starting point for an operator-managed `.env` file.

## Build and run

Build the image:

```bash
docker build -t geoqa-agent .
```

Run the configuration diagnostic before first use:

```bash
docker run --rm --env-file .env geoqa-agent python app.py --diagnose-config
```

Start the single-host Streamlit deployment:

```bash
docker compose up --build
```

The default app endpoint is `http://localhost:8501`.

## Storage strategy

- Mount `./outputs` to `/app/outputs` for runtime QA artifacts.
- Mount `./demo/output` to `/app/demo/output` if you want committed demo artifacts available in the container.
- Treat `review_status.json` as the current-state review file.
- Treat `review_history.jsonl` as the append-only audit trail for all review actions.

## Runtime behavior

- Deterministic QA remains available even if OpenAI settings are missing or agent reports are disabled.
- Set `GEOQA_AGENT_REPORT_ENABLED=false` when the environment should allow deterministic QA only.
- In OpenAI mode, timeout and retry behavior are controlled by:
  - `GEOQA_OPENAI_TIMEOUT_SECONDS`
  - `GEOQA_OPENAI_MAX_RETRIES`
  - `GEOQA_OPENAI_RETRY_BACKOFF_SECONDS`

## Recovery and retention

- Each run writes to a dedicated output folder under the configured output root.
- Keep deterministic artifacts, draft artifacts, and approved artifacts together per run for auditability.
- `review_history.jsonl` should be preserved for the life of the run folder.
- V2.1 does not implement destructive auto-cleanup. Recommended retention is to archive or remove old run folders using an operator-managed housekeeping process outside the application.


## V3 analyst operations

- `run_index.jsonl` is the recent-run source used by the analyst console.
- Review actions update `review_status.json`, append `review_history.jsonl`, and refresh the run browser state.
- Comparisons are persisted under `comparisons/<comparison_key>/` and indexed in `comparison_index.json`.
- Handoff exports now validate required analyst artifacts before creating `handoff_bundle.zip`.
- Fix-plan generation can use a custom playbook directory through `--playbook-dir`.

## V4 release hardening notes

- Primary CLI path for agent execution is `--agent-run --agent-task ...`.
- `--agent-report` remains available as backward-compatible routing to the `report` task.
- For release demos, use a grounded static draft file (for example `demo/output/static_v4_report.md`) when running static provider approval flows.

Recommended release-gate command:

```bash
python app.py demo/input/centreline_intersections_sample.zip --output-dir demo/output --agent-run --agent-task report --agent-max-steps 4 --llm-provider static --static-report-file demo/output/static_v4_report.md --approve-agent-report --reviewer-name "Demo Reviewer"
```
